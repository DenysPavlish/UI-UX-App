# Сигнал — клієнт Hacker News

Багатосторінковий застосунок на React: каталог історій Hacker News із пошуком, фільтрами й пагінацією, сторінка історії з деревом коментарів та «Обране», яке переживає перезавантаження.

- **Опублікований застосунок:** `https://ВСТАВТЕ-АДРЕСУ`
- **Репозиторій:** `https://github.com/ВСТАВТЕ-ЛОГІН/ВСТАВТЕ-НАЗВУ`

## Запуск

```bash
npm install
npm run dev         # розробка, http://localhost:5173
npm run build       # збірка в папку dist
npm run preview     # локальна перевірка збірки
```

Змінні (необов'язково, див. `.env.example`): `VITE_API_BASE_URL` — інша адреса API, `VITE_BASE` — підкаталог, якщо сайт не в корені.

## API

Hacker News Search API від Algolia, ключ не потрібен. База: `https://hn.algolia.com/api/v1`. Адреса задана в одному місці — `src/api/config.js`, усі запити — лише в `src/api/hn.js`.

| Що | Ендпоінт | Параметри |
|---|---|---|
| Пошук за популярністю | `GET /search` | `query`, `tags`, `numericFilters`, `page`, `hitsPerPage` |
| Пошук за датою | `GET /search_by_date` | ті самі |
| Одна історія з деревом коментарів | `GET /items/{id}` | — |
| Інші публікації автора | `GET /search?tags=author_{name},story` | `hitsPerPage=7` |
| Добірка для головної | `GET /search?tags=front_page` | `hitsPerPage=6` |

Поведінка, яку враховує застосунок:

- Порожній результат — це **HTTP 200** з `hits: []`, а не помилка. Каталог показує порожній стан.
- Неіснуючий `id` у `/items/{id}` дає **404** → сторінка «Не знайдено». Мережева помилка, 429, 5xx і зламана відповідь — окремі повідомлення.
- Нумерація сторінок в API з нуля (`page=0`), у застосунку й в адресі — з одиниці.
- Коментар — це теж елемент з `id`; `/items/{id}` для коментаря або варіанта опитування застосунок трактує як «не знайдено» (сторінка історій).
- Текст коментарів приходить як HTML, тому проходить через білий список тегів (`src/api/sanitize.js`).

### Де виконується кожен фільтр

Фільтрація **серверна** для всіх трьох, бо клієнт бачить лише одну сторінку з 12 результатів — клієнтський фільтр дав би «порожні» сторінки та неправдиві лічильники.

| Фільтр | Реалізація |
|---|---|
| Тип публікації | параметр `tags` (`story`, `show_hn`, `ask_hn`, `front_page`, `poll`, `job`) |
| Мінімум балів | `numericFilters=points>=N` |
| Сортування за датою | окремий ендпоінт `/search_by_date` замість `/search` |

## Сторінки

| Маршрут | Вміст |
|---|---|
| `/` | головна: короткий вступ, готові посилання на каталог із фільтрами, добірка з головної сторінки HN |
| `/catalog` | пошук, фільтри, сортування, пагінація; увесь стан — в адресі (`?q=&type=&minPoints=&sort=&page=`) |
| `/story/:id` | історія, дерево коментарів, окремий блок «Інші публікації автора» |
| `/favorites` | обране з localStorage, видалення, очищення з підтвердженням |
| `/about` | про застосунок, API, технології |
| `*` | сторінка 404 |

## Архітектура

```
src/
  api/         fetch, помилки, кеш, нормалізація, санітайзер, функції hn.js
  context/     FavoritesContext, ThemeContext
  hooks/       useResource, useStoryData, useFavorites, useTheme, useDebouncedValue, useDocumentTitle
  components/  Layout, StoryCard, FilterPanel, Pagination, StateViews, CommentThread, …
  pages/       Home, Catalog, Details, Favorites, About, NotFound
  utils/       форматування, параметри каталогу, повідомлення про помилки
  styles/      токени та SCSS
```

Де що живе:

- **URL** — пошук, тип, бали, сортування, сторінка, `id` історії. Посилання можна скопіювати, «Назад» відновлює стан.
- **Context** — «Обране» і тема: потрібні в шапці, на картках, на деталях і на власній сторінці.
- **Локальний стан** — відкрита панель фільтрів, текст у полі пошуку до паузи, згорнуті коментарі.
- **Кеш** — відповіді API, поза React (`src/api/cache.js`).

## Кеш

`Map` у пам'яті, ключ — повна адреса запиту. Разом зі значенням зберігається час запису; запис старший за **5 хвилин** вважається застарілим і видаляється при наступному читанні. Максимум 150 записів, найстаріші витісняються. Помилки в кеш не потрапляють. Хук `useResource` спочатку питає кеш: якщо там є свіжа відповідь, вона показується одразу, без скелетона й запиту — тому «Назад» з деталей до каталогу миттєвий.

## Хостинг і маршрути SPA

Застосунок — один `index.html`; маршрути `/story/123` існують лише в JavaScript. Без налаштування хостинг шукає файл `story/123`, не знаходить і віддає 404. Рішення — переписування будь-якого шляху на `index.html`:

- **Netlify** — `public/_redirects` (`/*  /index.html  200`) потрапляє в `dist`. Build command: `npm run build`, publish directory: `dist`.
- **Vercel** — `vercel.json` з rewrite на `/index.html`. Framework: Vite.
- **GitHub Pages** — `.github/workflows/deploy.yml` збирає командою `npm run build:pages`, яка копіює `index.html` у `404.html` (Pages віддає її для невідомих шляхів). Змінна `VITE_BASE=/<назва-репозиторію>/` виставляється в workflow; у Settings → Pages оберіть Source: GitHub Actions.

## Завдання підвищеної складності

1. **Ліниве завантаження сторінок** — `React.lazy` + `Suspense` у `src/router.jsx`; кожна сторінка збирається в окремий файл. Вхідний бандл ≈ 306 kB (98 kB gzip) без сторінок; сторінка завантажується при першому переході.
2. **Кеш зі строком придатності** — див. розділ «Кеш».
